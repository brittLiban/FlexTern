# Architecture Decision Records

Durable decisions a future engineer might reasonably ask "why did we do this?" about. Not for trivial code choices.

- Naming: `ADR-XXXX-short-description.md`, four-digit zero-padded, sequential.
- Use `TEMPLATE.md`.
- Never delete or rewrite an accepted ADR. To change a decision, write a new ADR and mark the old one `Superseded`, filling in both `Supersedes` / `Superseded By` fields.
- A review in `../reviews/` is advice. It becomes an ADR only when the founder accepts it.

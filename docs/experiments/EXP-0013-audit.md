# EXP-0013 Phase 0 — Independent audit of the EXP-0012 predictive-state code

Date: 2026-11-07 · Branch: `exp-0013-predictive-planning` (from `main` 7037503) · Scope: inspection only, no training, no code changes.
Labels follow AGENTS.md §7. Everything marked MEASURED below was observed in this session with the throw-away probe scripts quoted in the Evidence column (not committed; the numbers are reproducible with the EXP-0012 checkpoints in `~/ps_ckpt` and data in `~/ps_data`).

## 1. Verification of the seven suspected issues

| # | Claim | Verdict | Evidence (source location) |
|---|---|---|---|
| 1 | `evaluate.py` runs `net.enc()` on logically skipped frames | **CONFIRMED (bug)** | `evaluate.py:77` (S4 path) and `:81` call the encoder on the whole batch every step; skipping only zeroes the result afterwards (`z * validf`, `:83-87`). `enc_count` (`:93`) is a *logical* count. MEASURED: G_s0, 32 DEV episodes, 80 steps: trigger `full` → logical 1303 encodes, **true 2560 samples encoded**; trigger `fixed:0.25` → logical 331 encodes, **true 2560 samples encoded**. The encoder also runs on blackout gray frames and on already-finished episodes. All "encoder runs cut ~60 %" statements in EXP-0012 are therefore logical/analytical, not executed work. The same pattern exists in training (`models.py:173,177` encode all B×T frames incl. blackout/drop frames; EMA target `:199` encodes all frames, which is legitimate for a target) and in `dagger.py:39`. |
| 2 | The predictor is not used for action selection | **CONFIRMED (by design)** | `net.pred` is called only in the JEPA loss (`models.py:205`) and the analysis (`analyze_state.py:126-127`). No evaluation path calls it. There is no planner, no value/score head, no goal representation (the goal square is only visible in pixels). |
| 3 | The predictor outputs a next-observation embedding, not a belief-state transition | **CONFIRMED (intentional simplification)** | `pred = mlp(H+3 → Z)` (`models.py:122`) regresses the normalized EMA-encoder embedding of o_{t+1} (`:197-209`, cosine loss). The belief is `h_t` (GRU, `:152-155`); nothing predicts `h_{t+1}`. Feeding `ẑ` back into the GRU would be inconsistent: the GRU was trained on the *unnormalized* LayerNorm output `z` (`Encoder.ln`) with a validity flag, whereas `ẑ` is trained only under a cosine loss (scale unconstrained). Also the policy reads the *current* masked embedding directly (`policy(...zin)`, `:150-153`, amendment 2), so `h` alone is not a sufficient statistic for the action — a belief-only planner would be out of distribution. |
| 4 | Training data lack counterfactual action coverage | **CONFIRMED (quantified)** | `expert.collect` logs one action per visited state: expert action plus Gaussian noise σ∈{0,.1,.2} on dx,dy (`expert.py:37,45`); gripper is never perturbed. MEASURED on `train_s0_n2000`: mean \|a_exec−a_label\|=0.08, 10 % of steps deviate >0.3, gripper differs from the label in 0 % of steps; angle between executed and expert direction p50/p95/p99 = 3.4°/25°/90°. The DAgger set (`dagger_s1_n1500`, used by all arms) is broader (54 % of steps deviate >0.3, 8 % gripper differs, state distribution is the learner's own) but still has exactly one action per state and no resets, so *no state has more than one action followed by its consequence*. Same-state/different-action supervision does not exist. The simulator is numpy and fully copyable, so snapshot/reset-based counterfactuals are cheap to add (`BatchEnv` state is a handful of arrays). |
| 5 | Rollout benchmark and latency benchmark implement different skipping | **CONFIRMED (inconsistent)** | `latency.py` is batch-1 and does skip the encoder (`:57`), but (a) `kind != "pix"` falls through to the *learned trigger* (`:52-55`), so `fixed:K` would silently call `net.trig` and is not implemented; (b) it times only `DIST`, 15 episodes, whereas the success numbers come from `evaluate.rollout`; (c) blackout frames are skipped in `latency.py` but executed in `evaluate.py`. The reported "1.4–1.9× latency gain" and "60 % encoder cut" thus come from two different code paths. |
| 6 | The learned trigger is not a calibrated uncertainty estimator | **CONFIRMED** | `trig = mlp(H+3+POOL_DIM → 1)` is trained with MSE to regress a single detached cosine-style surprise value (`models.py:211-216`), on `valid_env` frames only. It outputs an unbounded point estimate of an error, with no predictive distribution, no coverage/calibration test, no ensemble. It also consumes `pool_feat` of the *current frame* (`evaluate.py:56,69`), i.e. it needs the pixels it is supposed to avoid reading (cheap, but not free, and not charged in `latency.py` for the camera read). Its threshold is tuned on DEV to hit a target encode fraction (`calibrate`), not to meet an error bound. |
| 7 | Ternary inference is fake quantization | **CONFIRMED** | `quant.py` (docstring and `fq_weight`) simulates numerics with STE; no packed kernel exists; `latency.py` docstring states quantized arms are not timed. Every ternary figure in EXP-0012 is quality (closed-loop) or analytical (`cost_model.py`). |

## 2. Further findings not in the directive

1. **The benchmark cannot test lookahead (critical).** `env.py:177-239` has no collisions, walls, hazards or irreversible actions; the straight-line expert (`expert.py:13-26`) is optimal and reaches 100 % on every condition (`test_expert_solves_every_condition`). The only terminal failure other than timeout is a wrong pick, which a goal-seeking trajectory does not trigger. Occlusion + blackout tests *memory*, not *planning*. By the directive's own rule ("if the oracle planner does not outperform a reactive controller on a task designed to require lookahead, the benchmark is unsuitable") OccPick2D as written is unsuitable for Phase 4; an oracle-dynamics planner is expected to tie a good reactive policy. A new, versioned environment variant (EXP-0013's own; `env.py` untouched) is required. See §5 decision D1.
2. **Observation status is conflated.** The cell receives a single `valid` float (`models.py:152-155`) that is 0 for environment blackout, for a training-time burst drop (`train.py:burst_drop`) and for an intentional skip. The three cases are physically different (a skip is a choice and the scene is observable; a blackout is not; a drop is simulated sensor loss). Separating them needs an extra input → a **model-interface change that invalidates all EXP-0012 checkpoints** for the new architecture (they remain usable as baselines).
3. **Rolling the state forward needs predicted proprioception.** The cell consumes `prop = (ee x, ee y, held, grip)` at every step. For candidate action sequences, `ee` is deterministic (clip(ee+Δ)) but `held` depends on whether the pick succeeds, which depends on the target position (a belief quantity). The directive's `rollout(state, actions, proprio_seq)` must either predict `prop` or restrict candidate plans to cases where it is computable; this must be an explicit model component.
4. **Scoring needs new heads.** There is no goal or value output. A permitted score must be a function of the belief and a *deployable* goal description (task colour, goal-zone location from the first frame or a goal embedding), e.g. learned heads for "target–gripper offset", "target–goal offset", "held". These can be *trained* with privileged labels but must not read privileged state at deployment (oracle control excepted).
5. **Planner cost vs encoder cost is structurally unfavourable here (ANALYTICAL).** Per-step MACs of the G model: encoder 1.13 M, cell 0.10 M, policy 0.034 M, predictor 0.033 M. One rollout step (cell+pred+policy) is 0.17 M, so N=50, H=5 costs 42.8 M MACs = **38× one encoder pass**. Skipping the encoder therefore cannot reduce total compute unless planning is applied sparsely, the rollout is a much smaller dynamics net than the current heads, or the real encoder is far larger than this 3-conv toy (EXP-0012 flagged the toy encoder:updater ratio as unrepresentative). Gate D (“reduces total inference work or latency after planning overhead”) can fail for reasons unrelated to the idea; it must be pre-registered with the encoder cost stated and with a representative-encoder sensitivity case labelled ANALYTICAL.
6. **Statistical power.** KI-022: success varies by up to 0.5 across training seeds at small budgets; EXP-0012 used 3 seeds (some arms fewer). Gate C needs a pre-registered effect size and ≥5 training seeds per decisive arm, or the comparison is not interpretable.
7. **Training time vs the 15-minute cap.** EXP-0012 took ~7 h for 28 models with two concurrent workers (KI-024), about 30 min per model-worker at 6000 steps × batch 48. A single recurrent training run is therefore roughly twice the cap: every learned-model training run will need explicit approval, or smaller budgets (which risk the seed-variance regime of KI-022).
8. **Novelty.** Latent-space MPC (PlaNet/Dreamer/TD-MPC family) and event-triggered/active perception are prior art (KNOWN, from literature; `EXP-0012-literature-review.md` covers part of this). The only candidate novelty is *learned joint allocation of perception and planning compute under a belief state*. No claim should be made before a targeted prior-art pass.
9. **Superseded instructions.** The first pasted directive in this session (with `[EXP-0013]` tags, a 10 % success gate, and a sleep-timeout change) was replaced by the Phase 0 directive. No OS power/sleep setting was changed; no simulator was installed.

## 3. Bugs vs intentional simplifications

| Item | Class |
|---|---|
| Encoder executed on skipped/blackout/finished rows (eval, DAgger collection, training) | **Bug** (measurement validity): inflates cost, makes "encoder cut" purely logical |
| `latency.py` ignores `fixed:K`, uses a different skip rule and subset of conditions | **Bug** (inconsistency) |
| `valid` merges blackout / drop / skip | Simplification with consequences (§2.2) |
| Predictor targets observation embedding; policy reads current `z` | Intentional (JEPA auxiliary + amendment 2) |
| Trigger = MSE-regressed surprise | Intentional, but mislabelled if called "uncertainty" |
| Fake quantization; no timed quantized path | Intentional, documented |
| Straight-line expert / no obstacles | Intentional for EXP-0012's question; unsuitable for planning |
| DAgger relabelling gives on-policy states, single action per state | Intentional; insufficient for dynamics supervision |

## 5. Proposed minimal corrective implementation, decisions needed, test and compute plan

**Founder decisions requested before Phase 1/2**
- **D1 (blocking for Phase 4):** approve building a small lookahead benchmark variant (e.g. blocking walls/narrow gaps or hazard cells so the greedy straight line fails, plus the existing occlusion/blackout/displacement) as `OccPick2D-LA`, with the existing env unchanged. Without it, Phase 4's oracle control will almost surely show no planning advantage.
- **D2:** accept that separating missing/skipped/occluded status changes the model interface, so EXP-0013 models are new (small) models; EXP-0012 checkpoints serve only as baselines.
- **D3:** state belief = GRU `h` with transition `h_{t+1} = f(h_t, a_t, p̂_{t+1})` trained directly (open-loop, latent consistency to the *closed-loop* `h` as stop-gradient target) rather than routing `ẑ` through the encoder-input path. Recommended.

**Phase 1 (fix pipeline).** Gather-based sub-batch encoding (`idx = nonzero(need_enc)`, scatter into zeros); three-state observation code (`OBS_ABSENT_BLACKOUT / SKIPPED / PRESENT`), applied identically in train and eval; one shared step function used by `evaluate`, `latency` and DAgger; instrumentation counters (true encoder calls and samples, MACs from `cost_model`, wall time per component, `torch.cuda.max_memory_allocated`/`tracemalloc` peak). Behaviour-preservation check: the new path must equal the old output bit-for-bit on non-skipped rows.

**Phase 2–3 (interfaces, counterfactual data).** `world_model.py` (`belief_init`, `correct(b, obs)`, `dynamics(b, a)`, `rollout(b, actions)`, heads for prop and for goal-relevant scores), `planner.py` (random shooting; CEM only if needed), `perception.py` (triggers), `eval_planning.py`. Counterfactual set: snapshot an env at sampled states, apply K=8 distinct action sequences (expert, perturbations, random, gripper toggles) of length ≤10, record resulting privileged state and observations; plus recovery episodes after injected displacement. Held-out layouts from the existing `dev`/`test` id ranges.

**Test plan.**
- Phase 1: encoder never called for skipped/blackout/finished rows (call-count and sample-count spies, parametrised over masks incl. all-skip and all-encode); skipped steps still advance state (h changes with action/prop); causal order (obs_t used before a_t; a_t affects only t+1); train/eval step equivalence; latency path = evaluation path; EXP-0012's 17 tests still pass.
- Phase 2: `rollout` equals iterated `dynamics` (software, with a known analytical linear dynamics model, error <1e-6); rollout never touches the encoder; privileged-state leakage test (planner output unchanged when privileged arrays are corrupted); EMA/target stop-gradient and collapse check (feature std).
- Phase 3: same-state/different-action predictions differ when true consequences differ; action-shuffled and zero-action controls; horizons 1/3/5/10; drift and correction-recovery curves; goal separation (probe).
- Phase 4: oracle-dynamics planner solves `OccPick2D-LA` and beats a reactive policy; shuffled-dynamics planner degrades; planner's first action differs for different goals; planner calls learned dynamics (call spy).
- Phase 5: trigger comparison at matched success, with executed-work and p50/p95 latency including planner and trigger.

**Compute estimate (ESTIMATED).** Phases 0–1: minutes of CPU. Phase 2–4 software demos (analytic dynamics, oracle planner, env variant): minutes to <1 h CPU. Counterfactual data generation: numpy, ~10–30 min. Each learned-model training run: ~15–30 min GPU-minutes per seed at the EXP-0012 budget (extrapolated from KI-024, not measured for the new model), so a 5-seed Gate C comparison of ~3 learned arms ≈ 8–12 GPU-hours **and needs founder approval per run**; I will first look for a smaller model/shorter budget that stays out of the KI-022 regime. Phase 6 (quantization) not estimated until Gate C passes.

**Proposed order after authorization:** Phase 1 → env variant + oracle planner (software only, Gate A) → counterfactual data → one small learned world model (needs approval) → Gate B.
